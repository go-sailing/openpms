## 1. 项目背景

传统项目管理系统（如 Jira、PingCode）只负责"任务的记录与流转"，任务的实际执行仍依赖人工。随着 AI 智能体（Agent）技术成熟，可以由不同角色的智能体承担项目中的具体工作（需求拆解、编码、测试等）。

本系统旨在构建一个**以智能体为执行主体**的项目管理系统：用户负责创建项目、定义任务并指派给智能体，系统基于**可插拔的 harness 底座**（默认 [opencode](https://github.com/sst/opencode)，可为每个智能体独立选择 DeepSeek Harness）调度智能体在指定工作目录中自主完成任务，实现"项目管理 + 自动执行"的闭环。

## 2. 产品目标

1. **智能体可管理**：支持创建、配置多个智能体，每个智能体拥有独立的人设（System Prompt）、经验记忆和工具能力，并内置常用角色模板。
2. **项目可组织**：支持多项目管理，以项目为单位聚合任务与协作上下文；每个项目通过成员列表圈定可参与的智能体，任务指派范围受控。
3. **任务可执行**：任务可指派给智能体，绑定工作目录，由智能体在其所选 harness 底座上真实执行，并跟踪任务状态。
4. **执行可调度**：提供自动调度能力，任务可按"创建即派发 / 定时触发 / 前置依赖完成"等方式自动进入执行，系统统一管控队列、并发与失败重试，减少人工干预。
5. **MVP 优先**：首期跑通"建项目 → 建任务 → 指派智能体 → 智能体执行 → 状态回写"的核心链路。

### 非目标（本期不做）

- 多租户、组织架构与细粒度权限体系；
- 智能体之间的自动协作编排（多智能体自动流水线）；
- 任务的甘特图、看板拖拽、工时统计等重型项目管理能力；
- 移动端原生应用。

## 3. 名词解释

| 名词 | 说明 |
| --- | --- |
| 智能体（Agent） | 基于某个 harness 底座运行的 AI 执行单元，具备独立 System Prompt、经验记忆、工具集与底座选择 |
| System Prompt | 定义智能体角色、职责、行为边界的系统提示词 |
| 经验记忆（Memory） | 智能体在历史任务中沉淀的、可在后续任务中复用的知识与经验 |
| 工具（Tool） | 智能体可调用的能力。**授权只覆盖 OpenPMS 自己提供的工具**（任务管理等，见 F-A-04/F-A-05）；文件读写、Shell 执行等由 harness 底座自带，不参与授权 |
| 项目（Project） | 任务与智能体协作的容器，具有名称、描述等元信息 |
| 项目成员（Project Member） | 被加入某项目成员列表的智能体；只有项目成员才允许被指派或调度执行该项目的任务 |
| 任务（Task） | 项目中的最小工作单元，可指派给一个智能体执行 |
| 工作目录（Workspace） | 智能体执行任务时可访问的本地文件目录 |
| 调度器（Scheduler） | 系统内置的任务调度服务，负责按触发规则将任务自动派发给智能体，并管控队列、并发与重试 |
| harness 底座 | 智能体执行任务所用的底层运行时，可选 opencode 或 DeepSeek Harness（dsh）；**每个智能体各自选择**，默认 opencode |
| opencode / DeepSeek Harness | 两种可选的 harness 底座，负责加载 Prompt、模型调用与工具执行 |

## 4. 用户与使用场景

### 4.1 目标用户

- **个人开发者 / 技术负责人**：希望用 AI 智能体团队辅助甚至自主完成软件开发项目。

### 4.2 典型场景

1. **场景一：组建智能体团队**
   用户首次进入系统，系统已预置项目经理、产品经理、开发工程师、测试工程师等默认智能体；用户可直接使用，或调整其 System Prompt 与工具权限。

2. **场景二：创建并推进项目**
   用户创建项目"官网重构"，编写项目描述，并把产品经理、开发工程师智能体加入项目成员列表；将任务"编写登录页 PRD"指派给产品经理智能体、"实现登录接口"指派给开发工程师智能体（指派人只能从项目成员中选择），并分别指定工作目录；启动后智能体在对应目录中执行，用户可在任务详情查看执行过程与结果。

3. **场景三：智能体积累经验**
   开发工程师智能体在多个任务中沉淀编码规范与踩坑记录，后续执行同类任务时自动携带相关经验记忆，输出质量持续提升。

4. **场景四：任务自动调度**
   用户一次性创建一批开发任务并选择"自动派发"，任务进入调度队列，开发工程师智能体每完成一个任务，调度器自动派发下一个；用户还可为"每日构建检查"任务设置每日凌晨定时触发；"接口测试"任务依赖"接口开发"任务，前置任务完成后自动开始执行，全程无需人工逐个启动。

## 5. 产品总体结构

```
OpenPMS
├── 智能体管理（Agents）
│   ├── 默认智能体模板
│   ├── 智能体 CRUD 与配置（Prompt / 记忆 / 工具）
│   └── 智能体任务管理能力
├── 项目管理（Projects）
│   ├── 项目 CRUD（名称、描述等）
│   └── 项目成员管理（加入/移除智能体，限定任务指派范围）
└── 任务管理（Tasks）
    ├── 任务 CRUD（名称、描述、指派人、工作目录、状态）
    ├── 任务执行（调度智能体，底座按智能体选择）
    ├── 任务自动调度（触发规则 / 队列 / 并发 / 重试）
    └── 执行记录与结果查看
```

## 6. 功能需求

### 6.1 智能体管理

#### F-A-01 默认智能体

| 项 | 说明 |
| --- | --- |
| 需求描述 | 系统初始化时自动生成若干常用角色智能体，开箱即用 |
| 默认角色 | 项目经理、产品经理、开发工程师、测试工程师（后续可扩展架构师、运维工程师等） |
| 预置内容 | 每个默认智能体预置与其角色匹配的 System Prompt、推荐工具集；经验记忆初始为空 |
| 验收标准 | 全新环境首次启动后，智能体列表中可见上述 4 个默认智能体，且均可直接被任务指派 |

#### F-A-02 智能体创建与编辑

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 名称 | 文本 | 是 | 智能体展示名，同一系统内唯一 |
| 角色描述 | 文本 | 否 | 一句话说明智能体定位 |
| 头像/图标 | 资源 | 否 | 未提供时使用默认图标 |
| System Prompt | 长文本 | 是 | 定义角色、职责、输出规范与行为边界 |
| harness 底座 | 枚举 | 是 | 该智能体执行任务所用的运行时：opencode / DeepSeek Harness（dsh），默认 opencode；切换后其任务改由新底座执行 |
| 模型配置 | 枚举/配置 | 否 | 指定底层模型；**候选随该智能体所选底座变化**（opencode 从本机实时拉取，dsh 取内置目录），也允许手动填写；留空则由底座自身的默认模型决定 |
| 工具集 | 多选 | 是 | 勾选该智能体允许调用的 **OpenPMS 工具**（见 F-A-04）；底座原生工具不受此项控制 |
| 状态 | 枚举 | 是 | 启用 / 停用 |

- 支持创建、编辑、删除、启用/停用智能体；
- 已被任务引用的智能体删除时需二次确认，删除后历史任务保留其名称快照（或采用"软删除"）。

**验收标准**：用户可成功创建自定义智能体；停用状态的智能体不可被新任务指派。

#### F-A-03 经验记忆

| 项 | 说明 |
| --- | --- |
| 需求描述 | 每个智能体拥有独立、持久化的经验记忆，执行任务时在 System Prompt 之后作为上下文注入（顺序见 F-T-03） |
| 记忆来源 | ① 用户手动维护；② 智能体在任务执行完成后**自动沉淀**（默认模式，无需用户确认），单任务沉淀条数设上限 |
| 记忆管理 | 支持查看、编辑、删除单条记忆；支持按任务来源检索；自动沉淀的记忆同样可事后编辑或删除 |
| 隔离性 | 各智能体记忆相互隔离，默认不共享 |
| 验收标准 | 智能体 A 产生的记忆不会出现在智能体 B 的上下文中；更新记忆后执行新任务，行为可体现记忆内容 |

#### F-A-04 工具调用与授权

| 项 | 说明 |
| --- | --- |
| 需求描述 | 智能体的**工具授权只覆盖 OpenPMS 自己提供的工具**（见 F-A-05），授权语义与 harness 底座无关：换任何底座，同一份授权的效果完全一致 |
| 底座原生工具 | 文件读写/编辑、Shell 命令执行、目录检索、网络访问等由 harness 底座自带，OpenPMS **不做按智能体的授权或裁剪**，各底座按自身默认行为提供 |
| 授权范围 | 5 个 OpenPMS 工具：查询我的任务、更新任务状态、回写任务产出、拆解子任务、改派任务；按智能体粒度启用/禁用 |
| 授权生效 | ① 未授权的 OpenPMS 工具不向底座注册（不可见）；② 即便被调用，服务端仍以「执行令牌 → 项目成员 → 工具授权」三重校验拒绝并记录审计 |
| 工作目录约束 | 执行前校验任务工作目录（存在、位于允许根目录之下）；并通过 System Prompt 约束智能体将文件与命令操作限制在该目录内 |
| 验收标准 | ① 未授权某 OpenPMS 工具的智能体调用该工具被拒绝，且可在审计中查到；② 授权后同一任务在两个底座下行为一致；③ 工作目录不存在或不在允许根目录内时任务被拒绝执行 |

#### F-A-05 智能体任务管理能力

| 项 | 说明 |
| --- | --- |
| 需求描述 | 智能体可通过任务管理工具参与任务流转，而非仅被动执行 |
| 能力范围 | 查询分配给自己的任务、更新任务状态、回写任务产出/结论；可由项目经理类智能体进行任务拆解与指派（创建子任务、改派），但指派人只能从当前项目成员（F-P-02）中选择 |
| 安全边界 | 智能体对任务的操作权限按角色配置，且只能访问其作为项目成员的项目内任务；操作行为全部留痕 |
| 验收标准 | 开发工程师智能体完成工作后可自行将任务状态置为"已完成"；项目经理智能体可将一个任务拆分为多个子任务并指派，且无法指派给非本项目成员的智能体 |

### 6.2 项目管理

#### F-P-01 项目创建与维护

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 项目名称 | 文本 | 是 | 同一用户下唯一 |
| 项目描述 | 长文本 | 否 | 项目背景、目标等 |
| 默认工作目录 | 路径 | 否 | 项目级根目录，新建任务时默认继承，任务可覆盖 |
| 项目状态 | 枚举 | 是 | 进行中 / 已归档，默认进行中 |
| 创建时间 / 更新时间 | 时间 | 自动 | 系统生成 |

- 支持项目的创建、编辑、查看、归档；
- 项目详情页聚合展示该项目下的任务列表与项目成员（见 F-P-02）；
- 删除项目采用归档或二次确认策略，归档项目不可新建任务、不可增减成员。

**验收标准**：创建项目后可在项目列表与详情中查看；任务必须归属于某一个项目。

#### F-P-02 项目成员管理

| 项 | 说明 |
| --- | --- |
| 需求描述 | 每个项目维护一份独立的项目成员列表，成员由系统中的智能体担任；**只有在成员列表中的智能体，才允许被指派或被调度执行该项目的任务** |
| 添加成员 | 从已启用的智能体中选择一个或多个加入项目；同一智能体在同一项目中不可重复加入；新建项目时成员列表允许为空，但为空时该项目无法创建任务 |
| 移除成员 | 支持将智能体移出项目；移除前若其在该项目下存在"待处理/排队中/执行中"的任务，须二次确认并给出处理选项：① 自动改派给其他成员；② 保留现状待人工处理（移除后这些任务暂停派发）。仅"已完成/失败/已取消"的历史任务不受影响 |
| 成员信息 | 展示智能体名称、角色、状态、加入时间、在该项目下的待办/进行中任务数 |
| 与智能体停用联动 | 智能体被停用后不可被新增为成员；已在成员列表中的停用智能体保留成员身份但不可承接新任务（与 F-T-05 的派发校验一致） |
| 智能体侧可见性 | 智能体通过任务管理工具（F-A-05）只能查询和操作其作为成员的项目下的任务；项目经理类智能体拆解/改派任务时，指派人同样只能选择本项目成员 |
| 验收标准 | ① 非项目成员智能体在该项目建任务的指派列表中不可选，直接指定时被后端拒绝；② 成员为空的项目无法创建任务并得到提示；③ 移除存在未完成任务的成员时必须经过确认流程，移除后其排队中任务不会被调度器派发 |

### 6.3 任务管理

#### F-T-01 任务创建与维护

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 任务名称 | 文本 | 是 | 项目内建议唯一 |
| 任务描述 | 长文本 | 是 | 任务目标、输入、交付要求 |
| 所属项目 | 关联 | 是 | 任务必须归属于一个项目 |
| 指派智能体 | 关联 | 是 | 只能指派给**当前项目成员**（F-P-02）中处于启用状态的智能体 |
| 工作目录 | 路径 | 是 | 智能体执行该任务时的文件操作根目录，默认继承项目配置 |
| 任务状态 | 枚举 | 是 | 见 F-T-02 状态机 |
| 优先级 | 枚举 | 否 | 低 / 中 / 高，默认中，参与调度队列排序 |
| 触发方式 | 枚举 | 是 | 手动 / 自动派发 / 定时 / 依赖触发，默认手动，详见 F-T-05 |
| 计划执行时间 | 时间 | 条件 | 触发方式为"定时"时必填，到达该时间后进入调度队列 |
| 重复规则 | Cron 表达式 | 否 | 设置后任务按周期重复触发（如每日凌晨）；不设置则仅触发一次 |
| 前置依赖任务 | 关联(多) | 否 | 触发方式为"依赖触发"时必填，全部前置任务完成后自动进入队列 |
| 失败重试策略 | 配置 | 否 | 最大重试次数（默认 0）、重试间隔/退避策略，详见 F-T-05；未配置时，被上游标记为"可重试"的瞬时错误仍会走兜底重试 |
| 父任务 | 关联 | 否 | 支持任务拆解形成子任务 |
| 创建人 | 关联 | 自动 | 创建任务的用户 |
| 创建/更新时间 | 时间 | 自动 | 系统生成 |

- 支持任务的创建、编辑、删除；
- 工作目录需做合法性校验（路径存在、当前用户有访问权限）；
- 指派校验：被指派智能体必须是任务所属项目的成员且处于启用状态，前后端均须校验，指派非成员时拒绝并提示；
- 定时与依赖配置需做逻辑校验：计划时间不能早于当前时间；不允许设置循环依赖；重复规则须为合法 Cron 表达式。

#### F-T-02 任务状态流转

任务状态及流转规则：

```
待处理(Pending) ──手动启动──▶ 执行中(Running) ──完成(成功)──▶ 已完成(Done)
      │                          │  ▲
      │(自动/定时/依赖触发)        │  └──自动重试(失败且次数未耗尽)
      ▼                          │
排队中(Queued) ──调度器派发──▶ 执行中(Running)
                                 │
                                 └──失败(重试耗尽)──▶ 失败(Failed)
待处理/排队中/执行中 ──取消──▶ 已取消(Cancelled)
```

> 任务执行成功后直接进入"已完成"，不设人工验收/驳回环节；用户如对结果不满意，可查看产出与日志后重新执行任务或新建返工任务。
> 周期重复任务每次触发产生一条新的执行记录；执行结束后任务回归"排队中"等待下一周期，用户停用调度后方可取消。上一次执行尚未结束时到达的周期不并发执行，先记录为"待补执行"；上一次执行结束后立即补执行一次（连续错过多个周期也只补一次），随后恢复正常周期节奏。

| 状态 | 含义 | 可变更方 |
| --- | --- | --- |
| 待处理 Pending | 手动任务已创建、等待用户启动 | 用户、智能体 |
| 排队中 Queued | 已满足触发条件，等待调度器派发执行 | 系统 |
| 执行中 Running | 智能体正在执行 | 系统、智能体 |
| 已完成 Done | 智能体执行成功并回写产出，任务终态（无需人工验收） | 系统、智能体、用户 |
| 失败 Failed | 执行异常且自动重试次数耗尽 | 系统、智能体 |
| 已取消 Cancelled | 人工取消 | 用户 |

**验收标准**：状态只能按上述流转规则变更，非法跳转被拒绝并提示；自动类任务创建或满足触发条件后必须先进入"排队中"，由调度器统一派发，不得绕过队列直接执行。

#### F-T-03 任务执行

| 项 | 说明 |
| --- | --- |
| 触发方式 | ① 手动触发：用户点击"开始执行"；② 自动触发：由调度器按 F-T-05 规则派发。两种触发共用同一执行引擎 |
| 执行过程 | 系统以任务的工作目录为运行根目录，基于**被指派智能体自身配置的 harness 底座**（opencode 或 DeepSeek Harness，默认 opencode）启动该智能体，按其工具权限执行；底座是智能体级属性，同一项目内不同智能体可各走各的底座，切换底座无需改动任务与项目数据。上下文注入内容与顺序见下方"上下文注入" |
| 上下文注入 | 按固定顺序组装：① 智能体 System Prompt → ② 该智能体的经验记忆（按 agent 隔离）→ ③ 运行时上下文，包括项目信息、**当前项目已完成（Done）的历史任务摘要**、当前任务信息与可用工具清单 → ④ 用户指令（任务描述）。历史任务为项目级共享上下文，包含项目内各成员智能体已完成任务的名称、结论/产出摘要与完成时间，不含失败、已取消或进行中的任务；内容设条数与 token 上限，按完成时间与相关度裁剪 |
| 过程可见 | 实时展示智能体的思考过程、工具调用与输出（执行日志）；日志需标明本次执行由手动还是调度触发 |
| 中断与重试 | 执行中任务可被用户中止；M1 起设默认执行超时 30 分钟（可全局配置/按任务覆盖），超时按失败处理；失败任务支持手动重试，或由调度器按任务配置的重试策略自动重试。**所有重试都在被中断的那次执行上接续**——复用同一条执行记录（状态回到"执行中"，日志续写）并在其会话上继续，避免从头重做；周期任务的新一轮触发属于新执行，不接续 |
| 并发约束 | 同一智能体同一时刻默认只执行一个任务（可配置并发上限）；手动启动且智能体忙碌时提示用户，自动任务则进入队列等待 |
| 产出回写 | 执行结束后，产出摘要与结论回写任务；智能体可按 F-A-05 更新状态、沉淀记忆 |
| 验收标准 | 指派开发工程师智能体在指定目录执行"创建 README.md"任务后，目录中实际生成该文件，任务状态正确流转且日志完整可查 |

#### F-T-04 任务查询

- 支持按项目、状态、指派智能体、关键字筛选任务；
- 任务详情包含：基础信息、执行历史、执行日志、产出物、关联记忆；
- 提供调度队列视图：展示"排队中"任务及其指派智能体、优先级、入队原因（自动派发/定时到达/依赖满足）、预计派发顺序。

#### F-T-05 任务自动调度

| 项 | 说明 |
| --- | --- |
| 需求描述 | 系统内置调度器，在无需人工逐个启动的情况下，按任务配置的触发规则自动派发任务给智能体执行 |

**（1）触发方式**

| 触发方式 | 行为 |
| --- | --- |
| 手动（默认） | 保持现状，由用户点击启动，不进入调度队列 |
| 自动派发 | 任务创建后立即进入"排队中"，智能体空闲时自动派发；适用于批量建任务、逐个消化的场景 |
| 定时触发 | 到达"计划执行时间"后入队；配置 Cron 重复规则后按周期重复触发，支持查看下次触发时间。周期到达时若上一次执行仍在进行，不并发执行：记录一次"待补执行"，上一次执行结束后立即补执行（错过多个周期只补一次） |
| 依赖触发 | 所有前置依赖任务均变为"已完成"后自动入队；任一前置任务为"失败/已取消"时该任务不触发并给出原因提示 |

**（2）调度策略**

- **派发顺序**：按优先级（高 → 中 → 低）排序，同优先级按入队时间 FIFO；
- **并发控制**：支持按智能体配置最大并发数（默认 1），并支持全局并发上限；调度器仅在对应智能体有空闲执行槽位时派发；
- **调度开关**：支持系统级与项目级的自动调度开关；关闭后已在队列中的任务暂停派发（保持"排队中"），恢复后继续；
- **暂停/恢复**：用户可暂停单个任务的调度（如临时不想执行的周期任务），暂停期间定时到达不触发，恢复后按下一周期执行。

**（3）失败自动重试**

- 任务执行失败后，若已配置重试次数（`retry_max > 0`）且未耗尽，任务自动回到"排队中"等待重试，执行记录中标注为第 N 次重试；
- 支持固定间隔与指数退避两种重试间隔策略；
- **可重试错误的兜底重试**：任务未配置重试策略（`retry_max = 0`）时，若失败原因被上游运行时标记为"可重试"（`isRetryable`，如网络不可达、上游 5xx、限流等瞬时故障），系统仍按兜底策略自动重试（默认最多 2 次、固定间隔 30 秒）；未被标记为可重试的失败（如参数配置错误、业务性失败）仍直接置为"失败"，不做兜底重试；
- 重试次数耗尽后任务进入"失败"，周期任务的失败不影响下一周期的正常触发。

**（4）可靠性要求**

- 调度队列与触发配置持久化：系统重启后，"排队中"任务不丢失、定时触发不遗漏（基于持久化的下次触发时间补偿）；
- 同一任务同一时刻只能被派发一次，防止重启或轮询重叠导致重复执行；
- 派发前置校验：被指派智能体仍为该项目成员且处于启用状态、工作目录有效；智能体被停用/删除、**被移出项目成员列表**或工作目录失效导致无法派发时，任务暂停派发并标记原因、通知用户，不得静默丢失；待成员关系恢复或人工改派后继续。

**验收标准**：

1. 创建 3 个"自动派发"任务指派给同一智能体（并发为 1），任务依次自动执行，执行顺序符合优先级与 FIFO 规则，全程无需手动操作；
2. 定时任务在计划时间后自动进入执行；配置合法 Cron 的任务可按周期重复触发，并能查看/暂停/恢复调度；周期到达而上一次执行仍在进行时不并发，上一次结束后立即补执行一次；
3. 依赖任务在全部前置任务完成后自动执行；存在前置任务失败时不触发并提示原因；循环依赖在创建时即被拒绝；
4. 配置失败重试（如最多 2 次、固定间隔）后，前两次失败可自动重新入队执行，第 3 次仍失败则任务置为"失败"；未配置重试策略的任务遇到被标记为可重试的瞬时错误（如网络不可达、上游 5xx）时同样自动重试 2 次后置为"失败"，遇到不可重试的错误则一次即置为"失败"；
5. 系统在任务排队期间重启，恢复后队列任务仍被正常派发且不重复执行；
6. 关闭项目级调度开关后，队列暂停派发，重新开启后恢复；
7. 被指派智能体在任务排队期间被移出项目成员列表后，该任务不再被派发并提示原因；重新加入或人工改派给其他成员后恢复派发。

## 7. 核心数据模型（逻辑）

```
User        1───* Project
Project     1───* Task
Project     *───* Agent           （项目成员关系，ProjectMember）
Agent       1───* Task            （指派关系，仅当该 Agent 为任务所属项目成员时合法）
Agent       1───* AgentMemory
Agent       *───* Tool            （授权关系）
Task        1───* TaskExecution   （每次执行一条记录）
Task        *───1 Task            （父子任务，可选）
Task        *───* Task            （前置依赖关系，依赖触发）
```

关键实体说明：

- **Agent**：id、name、role、system_prompt、model_config、status、max_concurrency（调度并发上限，默认 1）、是否内置、创建时间
- **AgentMemory**：id、agent_id、content、source_task_id、created_at
- **Project**：id、name、description、default_workspace、status、auto_schedule_enabled（项目级调度开关）、created_at
- **ProjectMember**：id、project_id、agent_id、joined_at、role_in_project（可选，项目内角色备注）；(project_id, agent_id) 联合唯一，是任务指派与调度派发合法性的依据
- **Task**：id、project_id、agent_id、parent_id、name、description、workspace、status、priority、result；调度相关：trigger_mode（manual/auto/scheduled/dependency）、scheduled_at、cron_expr、next_run_at、retry_max、retry_interval、retry_backoff、schedule_enabled（暂停/恢复）、queued_at、enqueue_reason、pending_fire（周期任务执行期间错过周期的待补执行标记）
- **TaskDependency**：id、task_id、depends_on_task_id（联合唯一）
- **TaskExecution**：id、task_id、status、trigger_type（manual/scheduler）、retry_no、started_at、finished_at、logs、error

> 调度队列可基于 Task 表中 status=queued 的记录 + queued_at/priority 排序实现，无需独立队列表；next_run_at 由 Cron 表达式持久化计算，用于重启后的触发补偿。

| 部署 | 支持单机本地部署，数据本地持久化 |

## 9. 主要业务流程

**任务执行主流程**：

1. 用户创建/选择项目 → 从智能体列表中添加项目成员（F-P-02）→ 新建任务，填写描述、从项目成员中选择指派智能体、确认工作目录；
2. 用户启动任务，系统校验项目成员身份、智能体状态与工作目录合法性；
3. 系统通过被指派智能体的 harness 底座拉起智能体会话，按"System Prompt → 经验记忆 → 运行时上下文（项目信息、当前项目已完成历史任务摘要、当前任务、可用工具）→ 用户指令"的顺序注入；
4. 智能体在授权工具集与工作目录内执行，过程实时回传日志；
5. 执行结束：成功 → 任务直接进入"已完成"并回写产出；失败 → 按重试策略处理或进入"失败"并记录原因；
6. 经确认的经验沉淀至该智能体记忆，供后续任务复用。用户可随时查看已完成任务的产出与日志，需要调整时重新执行或新建返工任务。

**自动调度流程**：

1. 用户建任务时选择触发方式（自动派发 / 定时 / 依赖触发）并配置对应规则与失败重试策略；
2. 任务进入调度体系：自动派发立即入队；定时任务由调度器在计划时间（或 Cron 周期）到达时入队；依赖任务在前置全部完成时入队；入队后状态为"排队中"；
3. 调度器轮询队列，按"优先级 + FIFO"及智能体/全局并发上限挑选可派发任务；
4. 派发前校验被指派智能体仍为该项目成员、处于启用状态且工作目录有效，校验通过则拉起执行（后续同主流程第 3–5 步），校验失败则暂停派发、标记原因并通知用户；
5. 执行失败时按重试策略自动重新入队；重试耗尽置为"失败"；成功则直接进入"已完成"；
6. 周期任务执行结束后计算并持久化 next_run_at 并回归等待；若执行期间已有周期到达（存在待补执行标记），则跳过等待立即再派发一次；
7. 用户可随时暂停/恢复单任务调度，或通过系统级/项目级开关整体管控。

## 10. 验收标准（整体）

1. 系统首次启动即存在项目经理、产品经理、开发工程师、测试工程师 4 个默认智能体；
2. 可创建/编辑/删除自定义智能体，并独立配置 System Prompt、经验记忆与工具权限；
3. 可创建项目（名称、描述等）并维护项目成员列表；项目任务只能指派给项目内启用的智能体，非成员无法被指派或调度执行；
4. 项目下可新建任务并指派智能体、指定工作目录；
5. 任务可手动启动执行，智能体在其所选 harness 底座上于指定工作目录真实完成操作，状态按状态机正确流转；
6. 支持自动派发、定时（含 Cron 周期）、依赖触发三种自动调度方式，队列按优先级与并发规则派发，失败可按策略自动重试；
7. 调度状态可观测（队列视图、调度日志），服务重启后队列不丢失、不重复执行；
8. 可查看任务执行日志与产出；智能体经验记忆隔离且可跨任务复用；执行任务时智能体可获得当前项目已完成历史任务摘要作为上下文；
9. 智能体的操作被限制在授权工具与工作目录范围内。

## 11. 依赖与风险

| 类型 | 内容 | 应对 |
| --- | --- | --- |
| 外部依赖 | 智能体运行时、工具机制、模型接入依赖**智能体所选 harness 底座**（opencode 采用其最新稳定版并跟进升级；DeepSeek Harness 为开发者预览版，存在破坏性变更风险） | 通过统一的运行时适配层封装调用，隔离各自 API 变化；底座为智能体级配置（默认 opencode，可在智能体编辑页切换），更换底座不影响任务与项目数据 |
| 安全风险 | 智能体可能越权使用文件/命令能力 | 执行前工作目录校验 + OpenPMS 工具按智能体授权 + 全量审计日志 + System Prompt 约束。**注意**：harness 原生工具（文件读写/编辑、Shell、网络）由底座自身提供，OpenPMS **不做授权裁剪、也不在执行期拦截命令**（命令黑名单功能已移除）；两个底座语义一致。需要硬隔离时应在 OpenPMS 之外解决（容器/受限用户/网络策略） |
| 质量风险 | 智能体产出不稳定，执行成功即自动完成、缺少人工把关 | 完整保留执行日志与产出供用户复核，支持重新执行/新建返工任务；失败重试兜底，依赖经验记忆持续改进 |
| 调度风险 | 服务重启或轮询重叠导致任务漏执行、重复执行 | 队列持久化 + next_run_at 补偿 + 派发互斥（单任务执行锁） |
| 数据风险 | 智能体误改工作目录文件 | 后续版本可引入 git 快照/回滚能力（本期评估） |

## 12. 迭代规划建议

| 阶段 | 范围 |
| --- | --- |
| M1（MVP） | 默认智能体 + 智能体/项目/任务基础 CRUD + **项目成员管理（成员限定指派范围）** + 单任务手动执行 + 日志查看 + **执行超时（默认 30 分钟）+ OpenPMS 工具授权** |
| M2 | 经验记忆沉淀与复用、智能体任务管理工具（状态回写/任务拆解）、**任务自动调度（自动派发队列 + 定时/Cron + 失败自动重试 + 调度开关）** |
| M3 | 依赖触发调度、多智能体协作编排、任务看板、执行快照与回滚 |
